## 1. What we are

**One-liner:** Your data, cleaned up and working for you.

**What we are:** A managed data team a company doesn't have to hire. We build and run the data foundation so their people can see what's happening, enter information easily, ask questions in plain English, and know what to do next.

**What we are not:**
- Not a staffing firm. We don't rent people by the hour.
- Not a software vendor selling licenses.
- Not a dashboard shop that builds a report and leaves.

**Positioning:** Bigger than a freelancer or consultant. Far easier and cheaper than a big-firm transformation. We are the data department for companies that don't have one, and the AI-ready layer for companies whose IT team already runs the infrastructure.

**The pitch in one line:** AI is only as good as the data under it. We fix the foundation first, so when you use AI, it's actually right.

## 2. The six steps

Every client engagement, every page of the website, and every sales conversation follows this flow.

| # | Step | Client-facing description | What actually happens |
|---|---|---|---|
| 1 | **Collect** | We find your data wherever it lives and bring it together. | Source inventory, connectors, file sync from SharePoint/OneDrive/Drive. |
| 2 | **Clean** | We fix duplicates, errors, and mismatches so your numbers agree. | Modeling, standardization, validation tests on every load, data dictionary. |
| 3 | **Secure** | Your data goes into a private, encrypted database built for your company. | Dedicated Snowflake account per client, role-based access, MFA, audit logging. |
| 4 | **See** | Live dashboards and a simple app to view status, enter updates, and ask questions. | Streamlit apps with input forms, live dashboards, plain-English Q&A. |
| 5 | **Act** | Every month we tell you what changed and exactly what to do next. | Insight Review with action items, owners, and due dates. Automated alerts. |
| 6 | **Own** | It's yours. Leave with a clean, organized database. No lock-in. | Contractual ownership. Full export or account handover within 30 days. |

## 4. Who we serve

Two paths. Every sales conversation and every website visitor is routed into one of them.

### Path 1: Small and growing businesses
- 10–250 employees, $2M–$100M revenue, no data team.
- Data lives in spreadsheets, QuickBooks, and one or two industry tools.
- **Model:** We host it in numarket's managed environment. Client owns the data.
- **Client effort:** Very low. Kickoff call, logins, a few hours of review.

### Path 2: Larger organizations
- 250+ employees, existing IT team, may already use Power BI, Azure, Snowflake, or an ERP.
- **Model:** Your platform or ours. If IT runs a platform, we build inside it. We work with IT, not against it.
- **Client effort:** Moderate. IT grants read access, a business sponsor, a security review.

### Industries (launch set)
Construction & Contractors · Manufacturing & Operations · Food Production & Catering · Healthcare & Clinics · Utilities & Energy · Finance & Professional Services · Logistics & Transportation · Real Estate & Property Management

Outreach focuses on one industry at a time. The offer itself works for any industry.

**Protection from vendor price increases:** pass-through clause in every contract, and all data kept in open formats so the engine can be changed without the client noticing.

## 8. Delivery stack

| Layer | Tool | Notes |
|---|---|---|
| Ingestion | Airbyte (open source) or Fivetran; APIs; SharePoint/OneDrive/Drive sync | Read-only connections wherever possible |
| Storage | Snowflake, one dedicated account per client under numarket's organization | Open formats (Parquet/Iceberg) where possible |
| Transformation | dbt | Tests run on every load; bad rows flagged, not published |
| Apps & dashboards | Streamlit in Snowflake | Warehouse runtime for small teams; externally hosted app with service connection for 100+ viewers |
| Plain-English Q&A | Snowflake Cortex | Business definitions written per client so answers are correct |
| Alerts | Snowflake tasks + email/Slack/Teams | Thresholds set with client |
| Website | Next.js, Three.js (react-three-fiber), GSAP, Tailwind, Vercel | See Section 11 |
| Scheduling / CRM / billing | Calendly · Airtable ("nuMarket HQ") · Wave | |

### Handling spreadsheets
- Recurring data entry moves into Workspace input screens. Excel stops being the source.
- Files that must stay in Excel are dropped in a shared folder and auto-synced. No manual transfers.
- Validation at entry, tests on load, audit trail on every change.

## 9. Security and data ownership

**Promises**
1. The client owns their data. The contract says so.
2. Every client gets a separate, encrypted database. Data is never mixed.
3. Least access: named accounts, multi-factor sign-in, read-only source connections.
4. Every change and login is logged.
5. Leave with everything within 30 days of exit.

**Operating rules**
- No client data on laptops or personal devices.
- Every contract: MSA with data-ownership clause, Data Processing Addendum, liability capped at fees paid, client responsible for accuracy of data they enter.
- Healthcare: HIPAA-eligible configuration and BAA on request (Business Critical edition).
- Insurance: cyber liability + professional liability (E&O) bound before first client signs.
- Incident notification to client within 72 hours of a confirmed incident.
- **Never claim a certification numarket does not hold.** Platform provider certifications may be referenced as the provider's.
- SOC 2 (via Vanta or Drata) planned once mid-market deals require it.

## 11. Interactive experience standards

Interactivity is how numarket sells. We **show** the journey from messy data to clear action instead of describing it. These standards apply to the website, demos, sales materials, and client Workspaces.

### Principles
1. **Show, don't tell.** Every major idea gets an interaction or animation, not a paragraph.
2. **Motion with meaning.** Every animation tells the story: messy → clean → secure → useful → action. No decorative motion.
3. **No jargon.** If a restaurant owner wouldn't understand it, rewrite it.
4. **Two audiences.** Small business and large organization each feel "this is for me" within 5 seconds.
5. **Always answer:** how hard, how long, how much.
6. **Fast.** Content is readable before any 3D loads.

### Signature experiences
| ID | Name | Where | What it does |
|---|---|---|---|
| 3D-1 | **The Data Journey** | Home, How It Works | Scroll-driven 3D scene: scattered file tiles (chaos color) stream into a filter ring, turn green, settle into a secured database core, then unfold into dashboard, input form, chat, and action-item panels. Ends with a key handoff ("It's yours"). |
| 3D-2 | **Pick Your Business** | Home, Solutions | Industry icons + Small/Large toggle. Clicking an industry shows its data sources flowing into the core and its sample dashboard, questions it can answer, and effort/timeline/price for that size. Each state has its own URL. |
| 3D-3 | **Change a Number** | Home, Demos | Live app demo: edit a budget or % complete, watch the dashboard, KPIs, and status update and an action item appear. Second tab: Ask Your Data with scripted Q&A. Labeled "Sample data." |
| 3D-4 | **Readiness Meter** | Getting Started | 3D ring fills from Level 1 to 5 as a visitor answers 5 questions. Feeds the cost and timeline estimator. |
| 3D-5 | **Secure Vault** | Security | Rotating database core inside layered shields (encryption, access, logging, backups). Hover a shield for a one-line explanation. |

### Technical requirements
- Next.js (App Router) + TypeScript, brand tokens as CSS variables (`app/globals.css`), light pages with dark "stage" sections.
- Three.js via `@react-three/fiber` + `@react-three/drei`; GSAP ScrollTrigger for scroll scenes; Framer Motion for UI transitions.
- 3D lazy-loaded (`ssr: false`), rendered only in viewport, render loop paused off-screen, DPR capped at 2.
- Fallbacks for mobile, `prefers-reduced-motion`, and no WebGL.
- Labels are HTML overlays, not 3D text.
- Lighthouse ≥ 90 desktop / ≥ 80 mobile. WCAG 2.1 AA. No horizontal scroll at 375px.
- Content lives in data files (`content/*.ts`), not inside components.

### Estimator logic (Getting Started)
- sources ≤ 3 AND users ≤ 15 AND employees < 100 → **Insight**
- sources ≤ 8 AND users ≤ 50 AND employees < 500 → **Operate**
- otherwise, or client platform selected → **Command**
- Readiness Level 1 (mostly spreadsheets): add 1–2 weeks and ~20% to setup.
- Output: tier, difficulty, client time, time to first dashboard, setup range, monthly range, what we need from the client. Always labeled "Estimate only."

```
├── components/                ← nav, footer, industry explorer, charts, forms, demos
│   └── journey/               ← 3D scenes (three.js): Data Journey + Security vault
├── app/                       ← one folder per page (Next.js App Router)
├── public/                    ← favicon and static files (the only files served as-is)
└── legacy/                    ← the previous single-page site, kept for reference
```

### Running the website
- `npm install`, then `npm run dev` (local preview at http://localhost:3000) or `npm run build`.
- Deployed on Vercel as a Next.js project (`vercel.json` sets the framework).
- To change a price, a phone number, or an industry: edit the file in `content/`. Every page that uses it updates.
- Demo dashboards are generated from row-level sample records in `lib/sample-data.ts`. Every KPI, chart, table row, and action item is calculated from those records, so filtered views always add up. Ratios are computed from summed parts, never averaged.
- Styling uses brand tokens defined once as CSS variables in `app/globals.css`.
- 3D scenes load only when scrolled near, pause off-screen, and fall back to a 2D storyboard for reduced-motion visitors or browsers without WebGL.
